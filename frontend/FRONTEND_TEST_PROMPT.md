You are auditing and hardening CampusEats in `frontend/` of VISard-Lizards. Use the existing Astro/TypeScript framework, tokens and conventions. Read applicable AGENTS.md, package.json, current branch/status, `FRONTEND_AUDIT.md`, `FRONTEND_CHECKLIST.md`, frontend API/types, Profile, and relevant components before changing them. Do not scan unrelated folders. Check current source rather than treating older reports as current evidence.

Objective: verify every existing frontend feature and failure branch; fix reproducible frontend defects; provide a complete prioritised fixes/improvements list and independently checkable evidence. Do not call this finished after a happy-path screenshot or a passing build.

1. Preserve local changes. Fetch teammate updates and report compared/merged refs; do not discard changes or alter another developer’s branch. Resolve integration conflicts while retaining newer backend contracts. Use the current authorized branch and obey the user's commit/push instructions.
2. Inventory routes, interactive controls, stored state and backend boundaries. Use all case IDs in `FRONTEND_CHECKLIST.md` as the baseline. Add cases for any newly found feature/state. Maintain per-case PASS/FAIL/BLOCKED/NOT RUN/NOT APPLICABLE status, expected/actual result, evidence, environment and bug reference. An unchecked or unavailable environment is not a pass.
3. Run the repository’s actual check/test/build/lint scripts if present. Report exact commands/results. Do not invent a lint command or treat type checking as lint. Add only useful regression tests for actual behavioural defects. Use existing dependencies; justify any necessary addition.
4. Run a responsive matrix at actual CSS widths 320, 360, 390, 430, 768, 1024, 1440, 1920; verify innerWidth, horizontal overflow, content clipping and focus clipping. Cover every onboarding/rating/login/chart state, not just initial routes. Include short viewport, landscape, 200%/400% zoom, enlarged font, software keyboard and safe areas. Test light/dark and EN/DE. Save screenshots for representative phone and wide layouts and failures.

Run touch drags for budget and priority reorder, pointer and keyboard equivalents, native dialog interactions, chart controls, Maps, favourite and meal stars. Existing personalized suggestions take precedence, max four unique mensas. Strings such as `Schnitzel with pommes` star as `Schnitzel`; do not replace starred strings with meal IDs. Verify filtering/promotion/unavailable-last rules together.
7. Verify all Zurich clock boundaries, yesterday-only recovery, DST, midnight/month/year transitions, duplicate rejection, dismissal/resolution persistence and the one-prompt-per-calendar-day cap. Verify CORS/public HTTPS API access on a real phone; localhost on a phone is the phone, not the developer’s PC.
10. Exercise every storage key with missing data, malformed JSON, wrong shapes/enums, denied access, quota errors, clearing and two-tab concurrent edits. Back up and restore pre-existing user browser data; use a separate test origin/profile when possible. Verify no whole-page crash, false Saved messages, lost unrelated profile fields or repeat prompt loops.
11. Verify current vs predicted crowd, returned interval/timezone, null vs zero, sufficient/insufficient data, 96 bins, sample size/freshness and preview labelling. Never substitute illustrative data as measured live crowd. Test empty weekdays, sparse bins, invalid/out-of-range values, selection preservation and non-hover accessibility.
12. Run full keyboard journeys, focus restoration when content disappears/reorders, labels/landmarks/live announcements, dark/image contrast and screen-reader checks where available. Translate dynamic errors/ARIA/tooltips as well as headings. Login/pass stays an explicitly labelled UI-only demo until real authentication exists; dummy credentials must never persist/log/transmit.
13. Run bounded local stress fixtures after functional correctness: large menus/stars, rapid repeated actions, long Unicode/HTML-looking inputs, slow network/CPU and repeated navigation. Define and measure responsiveness/payload/request/memory/layout-shift budgets. Do not flood shared production endpoints or claim stress success without measured results.
14. Fix confirmed frontend defects within scope, using the smallest coherent changes. Re-run targeted regression and required checks after edits. Preserve explicit product deferrals: no Make it Yours/cuisine/dislike/lunch-time screens, no automatic onboarding, only the chosen price tier, smaller photos and Maps beside mensa names. For backend-dependent work, document the exact contract/action needed instead of inventing success.
15. Deliver: (a) complete case ledger and feature/viewport/browser coverage; (b) prioritised bug/improvement backlog with confirmed/risk/decision distinctions, source references and reproduction steps; (c) changed files and meaningful tests; (d) exact commands/results and screenshots; (e) mocks, unavailable environments, schema/requirements decisions and remaining risks; (f) concise implementation order. Do not assert that all features work unless all relevant evidence supports it. Commit/push only as authorized. Send the final report to Discord channel `1558161627025637566` only when the current user instruction authorizes it, and verify the sent message/attachments.
